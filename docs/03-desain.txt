  nama, foto) hanya contoh, bukan acuan.

- Halaman per provinsi digabung ke katalog: /katalog?provinsi=<slug>.

- "Kapan terlihat" disimpan sebagai tanggal (pilih bulan & tahun).
- Koordinat mini map opsional; diisi lewat pin di peta kecil di form.
- Ikon kartu (resep/video/lokasi) hanya tampil jika datanya ada.
- Akun admin terpisah dari akun user biasa; admin tidak boleh menyetujui
  kirimannya sendiri.

Perubahan revisi 1 (tetap berlaku):

  jajanan di section "Terakhir Terlihat di".
- Video per langkah via link embed, vote kelangkaan, konfirmasi

Referensi struktur: mirip Cookpad (katalog -> detail -> upload), pembeda:
cerita/asal daerah, kelangkaan hasil voting, lokasi terkini, request.


=================================================================
1. ROLE PENGGUNA
=================================================================
User
- Belum login: lihat beranda, katalog, detail, request, profil orang,
  tentang.
- Sudah login: + upload jajanan/resep/langkah/foto, tambah lokasi
  terlihat, konfirmasi lokasi, voting kelangkaan, komentar, simpan,
  "saya sudah coba", lapor, buat/jawab request, notifikasi.
- Aksi yang perlu login saat belum login -> muncul overlay Masuk,
  setelah login kembali ke halaman/aksi semula.

Admin
- Semua hak user + setujui/tolak kiriman, tangani laporan, edit kecil,
  kelola kategori.
- Link "Admin" muncul di menu avatar jika role = admin.

2. SITEMAP
=================================================================
/                      Beranda
/katalog               Katalog + search + filter + urutkan
                       (query: ?q= &provinsi= &kategori= &urut= dst.)
/jajanan/[slug]        Detail jajanan (1 template untuk semua jajanan)
/request               Daftar request (tab Terbuka / Terjawab)
/request/[id]          Detail request + jawaban
/upload                Form kontribusi (perlu login): cek duplikat -> 7 langkah
/masuk                 Fallback login (utamanya overlay)
/profil/[username]     Profil publik user (tab Kontribusi saja)
/profil/saya           Profil sendiri: Kontribusi, Tersimpan, Status kiriman
/admin                 Dashboard moderasi (tab Kiriman, Laporan, Kategori)
/tentang               Tentang project + aturan kontribusi + lisensi

Overlay (modal, bukan halaman): Masuk, Cari, Urutkan, Bagikan, Lapor,
Lokasi baru, Tambah foto, Buat request, Jawab request, Edit profil,
Keluar dari form, Pratinjau kiriman, Tolak kiriman, Tambah kategori,
Notifikasi (dropdown).
Toast: notifikasi singkat setelah aksi (tautan disalin, laporan terkirim,
kiriman disetujui/ditolak, dll.).


=================================================================
3. USER FLOW
=================================================================
Flow A - Mencari jajanan
Beranda -> search / chip provinsi / "Lihat semua"
-> Katalog (filter + urutkan) -> Detail jajanan
-> baca cerita, resep, langkah, "Terakhir Terlihat di"
-> (opsional) simpan / komentar / vote -> overlay Masuk jika belum login

Flow B - Upload jajanan baru
Klik "Kontribusi" -> overlay Masuk jika belum login
-> Cek duplikat: ketik nama -> daftar hasil mirip
   -> "Tambah ke sini": tambah versi resep / lokasi / foto ke jajanan itu
   -> "Buat jajanan baru": masuk form
-> 1 Info dasar (wajib) -> 2 Cerita -> 3 Resep -> 4 Langkah pembuatan
-> 5 Lokasi terlihat -> 6 Vote kelangkaan -> 7 Review & kirim (wajib)
   (langkah 2-6 opsional, tombol "Lanjut / lewati"; draft tersimpan otomatis)
-> layar Mengirim -> layar Terkirim ("Menunggu moderasi")
-> hasil moderasi muncul di notifikasi + tab Status kiriman
-> ditolak: alasan tampil + tombol "Perbaiki & kirim ulang"

Flow C - Lokasi terlihat
Detail -> section "Terakhir Terlihat di"
-> "Saya lihat di tempat lain" -> overlay Lokasi baru -> moderasi
-> di kartu lokasi: "Masih ada" / "Sudah tidak ada"
-> "Masih ada" update tanggal terakhir dikonfirmasi

Flow D - Vote kelangkaan
Detail -> panel "Menurutmu seberapa langka?"
-> Umum / Mulai langka / Hampir punah / Punah
-> 1 user 1 suara, bisa diganti; label tampil setelah min. 3 suara
-> seri -> pilih yang lebih langka

Flow E - Moderasi (admin)
/admin tab Kiriman -> Lihat (overlay Pratinjau) -> Setujui / Tolak
(overlay Tolak, wajib alasan) / edit kecil
-> tab Laporan -> sembunyikan konten / abaikan
-> tab Kategori -> tambah / ubah kategori
-> semua aksi tercatat di moderation_logs

Flow F - Request
/request -> "Buat request" (overlay) -> user lain "Jawab"
(link ke jajanan yang ada atau upload baru) -> status Terjawab


=================================================================
4. ISI TIAP HALAMAN (RINGKAS, DETAIL LIHAT FIGMA)
=================================================================
Semua halaman: Navbar (atas) + Footer (bawah).
Navbar desktop: logo, Beranda, Katalog, Request, Tentang, search kecil,
  [Masuk] atau [lonceng + avatar], tombol "+ Kontribusi".

[BERANDA]
Hero (tagline + search + saran "Coba: ..."), 4 StatCard (jajanan,
provinsi, kontributor, lokasi), Hampir Punah, Jelajahi per Daerah (chip
provinsi -> /katalog?provinsi=), Baru Ditambahkan, Baru Terlihat, CTA.

[KATALOG]
Judul + jumlah hasil, search, tombol Urutkan (terbaru, terpopuler, A-Z,
paling langka), sidebar Filter (provinsi, kategori, bahan utama, cara
masak, rasa, kelangkaan, punya resep/video/lokasi), grid SnackCard
3 kolom, load more. Kosong: ajakan request / tambah jajanan.

[DETAIL JAJANAN]
Kiri: foto utama (+ thumbnail galeri jika > 1 foto, bisa menyusul).
Kanan: kategori, nama, nama lain, asal daerah, Simpan/Bagikan/Lapor,
panel RarityVote, info pengirim.
Tab: Cerita | Resep | Lokasi (n) | Komentar (n)
- Cerita & narasi + sumber
- Resep: pilih versi, porsi/waktu/kesulitan, Bahan, Langkah (RecipeStep:
  teks + foto + video opsional), Video lengkap, "Saya sudah coba",
  penilaian Berhasil / Kurang berhasil, badge Terverifikasi
- Lokasi (kolom kanan): MiniMap, SightingCard (fresh/stale/confirmed/
  reported) + link "Pesan online" jika ada, "Saya lihat di tempat lain"
- Komentar
Bawah: "Dari [provinsi] juga".

[UPLOAD]
Layar cek duplikat -> form: stepper kiri (7 langkah), form tengah,
panel bantuan kanan (tips + aturan konten). Tombol Kembali, Keluar,
Lanjut / lewati. Lalu layar Mengirim & Terkirim.

[PROFIL]
Header: avatar, nama, @username, daerah, bio, badge, StatCard
(kontribusi, lokasi, resep dicoba), Edit profil (profil sendiri).
Tab: Kontribusi | Tersimpan* | Status kiriman*  (*profil sendiri saja)

[REQUEST]
Tab Terbuka/Terjawab, kartu request, Buat request. Detail: jawaban.

[ADMIN]
4 StatCard (menunggu, laporan terbuka, total jajanan, disetujui minggu
ini), tab Kiriman | Laporan | Kategori, tabel dengan Setujui/Tolak/Lihat.

[TENTANG]
Tentang project, aturan kontribusi, kriteria masuk katalog, lisensi
(CC BY-SA 4.0), kontak.
Kriteria masuk katalog:
- Jajanan tradisional Indonesia (bukan kreasi modern / fusion)
- Ada nama dan asal daerah
- Foto milik sendiri atau berlisensi bebas (cantumkan kredit)
- Tidak mengandung kata kasar, SARA, atau promosi berlebihan
- Lokasi hanya tempat usaha / publik

  Label 16/14/12, Caption 12, Overline 11
Spacing: 4, 8, 12, 16, 20, 24, 32, 40, 48, 64, 80
Radius : 8 (sm), 12 (md), 16 (lg), 24 (xl), full
Shadow : Card, Raised, Sheet
Desktop: lebar frame 1440px, konten max ~1200px.
Rencana: token -> CSS variables + tailwind theme.

7. SCHEMA DATABASE (SUPABASE / POSTGRES)
=================================================================
Status konten: pending | approved | rejected | hidden
Kelangkaan: umum | mulai_langka | hampir_punah | punah

profiles
- id (uuid, = auth.users.id), username (unik), nama_tampil, avatar_url,
  daerah, bio, role (user | admin), created_at

provinces
- id, nama, slug, kode

categories
- id, nama, slug

snacks
- id, slug (unik), nama, nama_lain (text[]), province_id, daerah_detail,
  category_id, deskripsi_singkat, cerita, sumber_info,
  cara_masak (text[]), rasa (text[]), bahan_utama (text[]),
  cover_url, status, created_by, created_at, updated_at

snack_photos
- id, snack_id, url, caption, kredit, uploaded_by, status, created_at

recipes
- id, snack_id, judul_versi, bahan (jsonb), porsi, waktu_menit,
  kesulitan (mudah|sedang|sulit), video_url, verified (bool),
  status, created_by, created_at

recipe_steps
- id, recipe_id, urutan, instruksi, foto_url, video_url

sightings
- id, snack_id, nama_tempat, area, province_id,
  jenis (kios_tetap | keliling | musiman), maps_url,
  lat, lng (opsional, dari pin di form), tanggal_terlihat (date;
  dari pilihan bulan & tahun, disimpan tanggal 1), last_confirmed_at,
  order_url (opsional, link GoFood/GrabFood/ShopeeFood/WA),
  izin_publik (bool), status, created_by, created_at

sighting_confirmations
- id, sighting_id, user_id, masih_ada (bool), created_at

rarity_votes
- user_id, snack_id, nilai, created_at, updated_at (PK user_id+snack_id)

comments
- id, snack_id, user_id, isi, status, created_at

saves
- user_id, snack_id, created_at (PK gabungan)

tries
- id, recipe_id, user_id, berhasil (bool), foto_url, catatan,
  created_at  (= penilaian "Berhasil / Kurang berhasil")

banned_words
- id, kata  (kiriman yang mengandung kata ini ditandai untuk admin)

requests
- id, judul, deskripsi, province_id, status (open|answered),
  answered_snack_id, created_by, created_at

request_answers
- id, request_id, user_id, snack_id (opsional), isi, created_at

notifications
- id, user_id, tipe (approved|rejected|request_answered|...),
  target_type, target_id, pesan, dibaca (bool), created_at

reports
- id, target_type (snack|recipe|sighting|comment|photo), target_id,
  alasan, status (open|resolved), reported_by, created_at

moderation_logs
- id, target_type, target_id, aksi (approve|reject|hide|edit), alasan,
  admin_id, created_at

Keamanan (RLS Supabase):
- Publik hanya baca konten status = approved.
- User baca/edit kiriman sendiri yang masih pending/rejected.
- User hanya ubah vote, konfirmasi, simpan, notifikasi miliknya.
- Hanya admin ubah status; admin tidak boleh moderasi kiriman sendiri.
- Storage foto: maks 2 MB, jpg/png/webp.
- Hanya lokasi usaha/tempat publik, bukan alamat rumah.

MVP: profiles, provinces, categories, snacks, snack_photos, recipes,
recipe_steps, sightings, rarity_votes, reports. Sisanya menyusul.

8. RENCANA DEVELOPMENT TAMPILAN (TEMPLATE DASAR)
=================================================================
Tujuan: web "kosongan" yang tampilannya sama dengan Figma, isi data
dummy (file JSON/TS lokal), belum tersambung database.

Urutan:
1. Setup Next.js + Tailwind, pasang font & design token (bagian 6).
2. Komponen dasar: Button, Chip, Input, Checkbox, SearchBar, Avatar,
   Tab, Modal, Toast, Icon.
3. Layout: Navbar (guest/login), Footer.
4. Komponen jajanan: SnackCard, RarityBadge, StatCard, SectionHeader.
5. Halaman: Beranda -> Katalog -> Detail -> Upload -> Profil ->
   Request -> Tentang -> Admin.
6. Overlay Masuk & overlay lain.
7. Responsive mobile (ikuti page Mobile di Figma).
8. Sambung ke Supabase per halaman (sprint berikutnya).

Catatan:
- Angka, nama, foto di Figma = contoh. Data asli dari 20-30 data awal tim.
- Foto contoh dari Wikimedia Commons wajib cantumkan kredit/lisensi.
